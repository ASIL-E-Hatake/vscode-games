# 社内試用ガイド（v0.5.0）

> 対象: 試用に協力してくれる新人・研修担当・社内開発者
> フィードバックは GitHub の Issue「フィードバック」テンプレートで送ってください（チャットで伝えてもらっても構いません）。送り方は [4 章](#4-フィードバックの送り方)。

## 1. インストール

1. [Releases](https://github.com/ASIL-E-Hatake/vscode-games/releases) から最新の `hatake-gottani-x.y.z.vsix` をダウンロードする
2. 次のどちらかでインストールする
   - ターミナルで実行:
     ```bash
     code --install-extension hatake-gottani-0.5.0.vsix
     ```
   - VS Code の拡張機能ビュー（`Ctrl+Shift+X`）右上の「…」→「VSIX からのインストール…」でファイルを選ぶ
3. 左端のアクティビティバーに鍋のアイコンが出れば完了。クリックするとメニューが開く

- 対応: VS Code 1.120 以上（Windows / Mac / Linux）
- **v0.3.0 以前を使っている場合は、v0.4.0 だけは同じ手順で手動で上書きインストールする**（記録や個人リンクは消えない）
- v0.4.0 以降は、拡張機能が新しい版を確認して知らせる。通知の「更新する」を押すとダウンロード・インストールされ、「再読み込み」で新しい版になる
  - ホームの「バージョン」欄に、今のバージョン・最新のバージョン・最後に確認した日時が出る。「更新を確認」（またはコマンド「ごった煮: 更新を確認」）で手動でも確認できる
  - 設定 `hatake-gottani.update.mode`: `notify`（既定。通知してボタンで更新）/ `auto`（自動でインストールし、再読み込みを案内）/ `off`（確認しない）
  - 社内のネットワーク（プロキシ・フィルタ）で GitHub に接続できない場合は確認できない（自動確認では何も表示しない。ホームに「確認できませんでした」と出る）。そのときは今までどおり Releases から vsix をダウンロードして上書きインストールする
- アンインストール: 拡張機能ビューで「Hatake ごった煮ツールボックス」→「アンインストール」

## 3. 知っておいてほしいこと（既知の制限）

- **外部への通信は、アップデートの確認だけです**（GitHub Releases に新しい版があるかの確認と vsix のダウンロード。送るのは通常の HTTP リクエストのみで、記録や利用者の情報は送らない）。設定 `hatake-gottani.update.mode` を `off` にすると、通信を一切しません。記録や個人リンクは自分の PC（VS Code の保存領域）にだけ保存されます。
  - 個人リンクは VS Code の Settings Sync をオンにしていれば、ほかの PC にも同期されます
- 社内リンクは同梱していません。チームで共有する方法は [README の「リンクをチームで共有する」](../README.md#リンクをチームで共有する) を参照
- 効果音は既定でオフです（設定 `hatake-gottani.sound.enabled`）
- ゲームを表示したくない場合は、設定 `hatake-gottani.games.enabled` をオフにするとメニューから消えます
- アイコンは仮のデザインです
- ショートカットの表記は Windows が基準です（はじめての VS Code の画面では Mac 表記に切り替えられます）

## 4. フィードバックの送り方

GitHub の Issue に、テンプレート「フィードバック（感想・不具合・要望）」で書いてください。開き方は 3 通りあります。

| 開き方 | 記入済みになる項目 |
|---|---|
| **おすすめ**: メニューの「ホーム」→「フィードバックを送る」、またはコマンドパレット（`Ctrl+Shift+P`）で「ごった煮: フィードバックを送る」 | OS・VS Code のバージョン・テーマ・拡張機能のバージョン |
| [このリンク](https://github.com/ASIL-E-Hatake/vscode-games/issues/new?template=1-feedback.yml) を開く | なし |
| GitHub の Issues →「New issue」→「フィードバック（感想・不具合・要望）」を選ぶ | なし |

ブラウザで GitHub にログインした状態で開いてください。テンプレートの項目:

| 項目 | 書いてほしいこと |
|---|---|
| 種類（必須） | 不具合 / 分かりにくい・使いにくい / こんな機能・内容がほしい / コンテンツの誤り / よかった点 / その他 |
| 機能 | どの画面のことか（複数選べる） |
| 内容（必須） | 「何をしようとして」「どうなったか」「どうなってほしいか」。スクリーンショットはドラッグ＆ドロップで貼れる |
| 再現手順 | 不具合のとき、どう操作したら起きるか |
| どのくらい困っているか | 使えない / 回避できる / 気になる程度 / 困っていない（要望・感想） |
| 環境・バージョン | コマンドから開いた場合は記入済み |

- 「よかった点」も大歓迎です（残す・伸ばす判断に使います）
- 社内の URL・個人情報・パスワードは書かないでください（Issue は GitHub に保存されます）
- 届いたフィードバックは [機能バックログ](02-feature-backlog.md) に反映します

## 5. 研修担当の方へ

- 研修用のリンク集は、ファイル（YAML / JSON）を作って共有フォルダに置き、各自の設定 `hatake-gottani.links.sharedFiles` にパスを指定してもらうと、ファイルの更新が全員に反映されます
- 研修用のリポジトリに `.vscode/hatake-gottani.links.yaml` を置けば、そのフォルダを開いた人全員にリンクが表示されます（フォルダを「信頼済み」にしている場合）
- **今週の課題に合わせた問題集**（出力当てクイズ・バグ探しの問題、タイピングのお題）は、問題パックとして配れます（形式は [問題パック](06-content-pack.md)）
  1. `week3.pack.yaml` のようなファイルを作り、答えは手元で実際に実行して確かめる（拡張機能はパックの問題を実行して検査しません）
  2. 共有フォルダに置き、受講者に設定 `hatake-gottani.contentPacks.sharedFiles` にパスを書いてもらう（例: `["//fileserver/training/week3.pack.yaml"]`）。ファイルを更新すると、ゲームを開き直したときに反映されます
  3. 受講者は各ゲームのモード「問題パック」で遊ぶ（自己ベストは同梱の問題とは別に記録）。終わった週のパックは「問題パック」画面で無効にできます
  4. 共有フォルダを使えないときは、ファイルを配って「問題パック」画面の「パックをインポート」で取り込んでもらう。課題のリポジトリに `.vscode/hatake-gottani.pack.yaml` として入れておく方法もあります（フォルダを信頼済みにしている場合）
- 辞書・チートシートは「調べ方・書き方」を示すもので、研修課題の解答は載せていません
