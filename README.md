# Hatake ごった煮ツールボックス（hatake-gottani）

新人研修・日々の開発で使う VS Code に慣れてもらうための、役立ち機能とミニゲームを詰め込んだ社内向け VS Code 拡張機能です。

- アクティビティバーの専用アイコン → サイドバーのメニュー → エディタ領域に表示
- 役立ち機能: はじめての VS Code / Linux コマンド辞書（忘れがちコマンド集付き） / 言語別チートシート（Java・Python・JavaScript・Ruby・Git） / Git 困ったとき辞書 / エラーメッセージ辞書 / 技術用語図鑑（出会った用語を集める） / 公式リンク集
- ゲーム（1 プレイ 1〜3 分。難易度・ゴースト対戦・苦手の復習つき）: コードタイピング / 反射神経テスト / スライドパズル / ショートカット早押しクイズ / 出力当てクイズ / バグ探し
- ツール: 問題パック（自分やチームで作った問題をゲームに追加する） / cron 式の組み立て（フォームで作る・貼った式を日本語で解説して次の実行日時を表示）
- 外部への通信は、アップデートの確認（GitHub Releases に新しい版があるかの確認と、vsix のダウンロード）だけです。記録や個人リンクは自分の PC の VS Code にだけ保存され、送信しません

## インストール

[Releases](https://github.com/ASIL-E-Hatake/vscode-games/releases) から `hatake-gottani-x.y.z.vsix` をダウンロードし、次を実行します（VS Code 1.120 以上）。

```bash
code --install-extension hatake-gottani-x.y.z.vsix
```

### アップデート

v0.4.0 からは、拡張機能が GitHub Releases に新しい版があるかを確認します（起動時と 24 時間ごと。送るのは通常の HTTP リクエストだけです）。新しい版があると通知が出るので、「更新する」を押すとダウンロード・インストールされ、「再読み込み」で新しい版になります。ダウンロードした vsix は、リリースに添付した `SHA256SUMS` と一致したときだけインストールします。

- 今のバージョン・最新のバージョン・最後に確認した日時は「ホーム」の「バージョン」欄に表示されます。手動で確認するには、ホームの「更新を確認」かコマンド「ごった煮: 更新を確認」
- 設定 `hatake-gottani.update.mode`: `notify`（既定。通知してボタンで更新）/ `auto`（自動でインストールし、再読み込みを案内）/ `off`（確認しない。外部への通信を一切しない）
- v0.3.0 以前を使っている場合は、v0.4.0 だけは上の手順で手動で入れ直してください

感想・不具合・要望は、メニューの「ホーム」→「フィードバックを送る」（またはコマンド「ごった煮: フィードバックを送る」）から GitHub の Issue で送れます。

VS Code の拡張機能ビュー（`Ctrl+Shift+X`）右上の「…」→「VSIX からのインストール…」からも入れられます。詳しくは [社内試用ガイド](docs/05-trial-guide.md) を参照してください。

## リンクをチームで共有する

社内 Wiki などのリンクは拡張機能に同梱していません。次のどれかの方法で追加・共有できます。

| 方法 | やり方 | 向いている用途 |
|---|---|---|
| 個人リンク | リンク集画面の「リンクを追加」 | 自分用のブックマーク |
| ファイルを配る | 「エクスポート」で書き出したファイルを渡し、受け取った人が「インポート」 | 一度だけ配りたいとき |
| 共有ファイル | 共有フォルダに置いたファイルのパスを設定 `hatake-gottani.links.sharedFiles` に指定 | 部署・チームで常に最新を共有したいとき（ファイルを更新すれば全員に反映） |
| ワークスペース | プロジェクトのリポジトリに `.vscode/hatake-gottani.links.yaml` を置く | プロジェクトのメンバー全員に見せたいとき |

ファイルの形式（YAML / JSON。リンクの配列だけでも可）:

```yaml
name: 開発部リンク集   # 省略可
links:
  - title: 開発規約
    url: https://wiki.example.co.jp/dev/rules
    note: コーディング規約とレビュー基準   # 省略可
    category: 社内規約                     # 省略可
    tags: [規約, レビュー]                  # 省略可
```

- URL は `http://` / `https://` のみ有効です。不正な行は読み飛ばし、画面に警告を表示します。
- ワークスペースのリンクは、そのフォルダを信頼済みにしている場合だけ読み込みます。

## 問題パック（自作の問題を追加する）

出力当てクイズ・バグ探しの問題、コードタイピングのお題を、自分やチームで作って JSON / YAML のファイル（1 ファイル = 1 パック）で追加できます。
追加した問題は各ゲームのモード「問題パック」で遊べ、自己ベストは同梱の問題とは別に記録します。**パックの問題は実行して検査されていません**（同梱の問題は CI で実行して答えを確かめています）。

| 方法 | やり方 |
|---|---|
| 取り込む（個人） | メニュー「ツール」→「問題パック」の「パックをインポート」、またはコマンド「ごった煮: 問題パックをインポート…」 |
| 共有ファイル | 共有フォルダに置いたファイルのパスを設定 `hatake-gottani.contentPacks.sharedFiles` に指定（ファイルを更新すれば反映） |
| ワークスペース | 課題のリポジトリに `.vscode/hatake-gottani.pack.yaml` を置く（フォルダを信頼済みにしている場合だけ読み込む） |

研修担当が「今週の課題に合わせた問題集」を共有フォルダに置き、受講者に設定へパスを書いてもらう、という使い方を想定しています。
パックごとに有効 / 無効を切り替えられ、不正な問題は読み飛ばして件数を表示します。形式と例は [問題パック](docs/06-content-pack.md) を参照してください。

## 開発

Node.js 22 と VS Code が必要です。

```bash
npm ci
npm run verify
```

- VS Code でこのフォルダを開き **F5** で拡張機能開発ホストが起動します。
- `npm run verify:full` で全テスト（L1〜L6）を実行し、`test-results/index.html` にスクリーンショット付きのレポートを出力します。

詳しくは [開発ルール](docs/03-development-rules.md) と [テスト戦略](docs/04-test-strategy.md) を参照してください。
