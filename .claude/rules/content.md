# コンテンツ（データ）作成ルール

- 形式: 辞書・リンク・問題は YAML、チートシートは Markdown。対応する JSON Schema（`content/schemas/`）に従う。
- 追加・変更後は `npm test`（スキーマ検証を含む）を通す。
- 文体: です・ます調ではなく、簡潔な体言止め・常体で統一（例: 「ファイルを一覧表示する」）。
- 新人が読む前提で、専門用語には初出時に一言説明を付ける。
- 研修課題の解答になるような完成コードは載せない。構文と小さな使用例にとどめる。
- コード例は実際に動作するものにする。OS 依存がある場合は明記（例: `macOS では sed -i ''`）。
- 破壊的なコマンド（`rm -rf`、`git reset --hard`、`chmod -R 777` 等）には `danger: true` と注意文を付ける。
- リンクは公式サイト・一次情報を優先し、`https://` のみ。社内リンクは `content/links/internal.yaml` に分ける（公開リポジトリ化に備える）。
- 外部サイトの文章をそのまま転載しない（著作権）。自分の言葉で要約する。
