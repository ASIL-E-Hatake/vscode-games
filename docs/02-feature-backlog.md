# 機能バックログ（優先度付き）

> ステータス: ドラフト v0.1（2026-10-14）
> MVP の詳細は [01-mvp-design.md](01-mvp-design.md) を参照。
> **どのバージョンで作るか（予定・進み具合）は [ロードマップ](roadmap.md) で管理する。** このファイルはアイデアと優先度・工数の一覧。

## 凡例

| 優先度 | 意味 | 目安 |
|---|---|---|
| **P0** | MVP（v0.1.0） | 最初のリリースに必須 |
| **P1** | 次に作る（v0.2〜0.3） | 研修・日常利用での効果が高く、基盤の範囲で作れる |
| **P2** | いずれ作る | 効果はあるが工数が大きい／P1 の成果を見て判断 |
| **P3** | アイデア枠 | 面白いが検証・合意が必要 |

- **工数**: S = 〜1 日 / M = 2〜4 日 / L = 1 週間以上（1 人換算の目安）
- **対象**: 新 = 新人向け / ベ = ベテラン向け / 共 = 共通
- **★** = 今回の提案（依頼にはなかったが「あったら面白い・役立つ」と考えたもの）

## 2. P1 詳細（次に作る）

### ★ `vscode-missions` VS Code 操作ミッション（新人向けの目玉）
VS Code に慣れること自体を「ミッション」にする。チュートリアルを読ませるのではなく、**実際の VS Code 操作を API で検知して自動でクリア判定**する。
- 例: 「新しいファイルを作って保存しよう」「Ctrl+P でファイルを開こう」「ターミナルを開こう」「単語を一括置換しよう」「分割エディタで 2 ファイルを並べよう」「拡張機能ビューを開こう」
- 検知: `workspace.onDidSaveTextDocument`、`window.onDidChangeActiveTextEditor`、`window.onDidOpenTerminal`、`window.onDidChangeVisibleTextEditors` 等
- 段階: 初級（ファイル操作）→ 中級（検索・置換・分割）→ 上級（マルチカーソル・Git 操作）
- 進捗は Storage に保存し、ホームにスタンプ表示
- 補足: VS Code 標準の Walkthrough（`contributes.walkthroughs`）でも一部実現可能なので、導入部は Walkthrough、本編はこの機能、と使い分けを検討

### ★ `game-cursor-golf` カーソル移動ゴルフ
**本物のエディタ上で遊ぶ**ゲーム（`kind: 'command'`）。サンプルコードを開き、デコレーションで光らせた目標位置へ、なるべく少ないキー操作でカーソルを移動させる。
- `Ctrl+←/→`（単語移動）、`Home/End`、`Ctrl+G`（行ジャンプ）、`Ctrl+Shift+\`（対応括弧）などを自然に覚えられる
- 判定: `window.onDidChangeTextEditorSelection` で移動回数と到達を計測、「パー」との比較でスコア
- 10 ホール × 約 10 秒 = 2 分弱。ベテランも腕前を競える

### ★ `error-dict` エラーメッセージ辞書（✅ 実装済み）
AI を使わない研修で最も詰まるのは「エラーの意味が分からない」こと。研修言語のよくあるコンパイル/実行時エラーについて「**意味・よくある原因・確認ポイント**」を載せる（修正後のコードそのものは載せない）。
- エラーメッセージの一部を貼り付けて検索（✅ 照合用の文字列 `patterns` が長く一致したものから表示。言語の絞り込み付き）
- ✅ 各エラーに「そのエラーが出るコード」を付け、`npm run test:snippets` で実際に実行してメッセージを確かめる
- 発展: 「問題」パネル（`languages.getDiagnostics`）のエラーを右クリック →「ごった煮辞書で調べる」

### ★ `game-output-quiz` 出力当てクイズ
短いコードを見て「何が出力されるか」を 4 択で答える。1 問 10〜15 秒 × 10 問。
- 言語別・難易度別。解説付き（間違えた問題だけ解説を表示）
- コードを「読む力」を鍛える。コンテンツは YAML で追加でき、講師・ベテランが問題を作れる

### ★ `game-shortcut-quiz` ショートカット早押しクイズ（✅ 実装済み）
「コマンドパレットを開く」→ 正しいキーを押す／選ぶ。60 秒で何問解けるか。
- 技術メモ: Webview 内でも一部のキー（`Ctrl+P` 等）は VS Code 側に奪われる可能性があるため、**キー入力方式が使えないキーは 4 択方式**にフォールバック。実装前に検証が必要
  - ✅ v0.2.0 では全問 4 択方式で実装（キー入力方式は採らない）。1〜4 キー・矢印キー + Enter・クリックで回答
- `vscode-guide` のショートカットデータを流用（✅ OS に合わせて Windows / Linux・Mac の表記を切り替え。誤答は同じカテゴリのショートカットを優先）
- ✅ 結果画面に正解数・回答数・正答率・間違えた問題（操作名と正しいショートカット）を表示

### `framework-guide` 主要フレームワークの基礎知識
`cheatsheet` と同じ仕組み（「対象 × 目次」形式の Markdown）で、主要フレームワークの「最初に知っておくべきこと」をまとめる。
- 共通の目次: 概要・何に使うか / ディレクトリ構成 / 起動・よく使う CLI コマンド / リクエストの流れ（MVC 等） / 設定ファイル / テスト / 公式ドキュメントへのリンク
- 候補（言語に合わせて）:
  | 言語 | フレームワーク |
  |---|---|
  | Ruby | Ruby on Rails（`rails new` / `generate` / `db:migrate`、MVC・ルーティング・ActiveRecord の基本） |
  | Java | Spring Boot（アノテーション・DI・`@RestController`）、Maven / Gradle の基本 |
  | Python | Django、Flask / FastAPI |
  | JavaScript | Node.js + Express、React / Vue の基本概念、npm の基本 |
- 一度に全部作らず、社内で使っているものから 1 つずつ追加する（コンテンツ追加のみで増やせる）
- 研修方針に合わせ、チュートリアルの完成コードは載せず「構成と概念・調べ方」を中心にする

### `git-dict` Git コマンド辞書・状況別レシピ
`linux-dict` の仕組みを流用。コマンド単位に加え「間違えてコミットした」「ブランチを切り忘れた」など**状況から引けるレシピ**を用意。危険なコマンド（`reset --hard`、`push --force`）には警告表示。
- ✅ 実装済み（v0.2.0）: 「Git 困ったとき辞書」として状況から引くレシピ 41 件（`content/git-recipes/`）。検索・分類の絞り込み・コピー・危険表示・関連レシピへの移動。コマンドは L2 で `git <サブコマンド> -h` と突き合わせて検査。コマンド単位の辞書は未実装（チートシートの Git と合わせて今後検討）

### ★ `game-regex` 正規表現パズル
「マッチさせる文字列」と「マッチさせない文字列」が提示され、条件を満たす正規表現を書く。短いほど高得点。VS Code の検索（`Alt+R` 正規表現モード）の実用にも直結。

### ★ `game-radix` 進数変換フラッシュ
2 進・8 進・10 進・16 進の変換を 60 秒で何問解けるか。発展で ビット演算（AND/OR/XOR/シフト）モード。基本情報技術者試験対策にも。

### ★ `break-timer` 休憩タイマー
ステータスバーに常駐するポモドーロ風タイマー。25 分作業 → 「5 分休憩しませんか？ ミニゲームを開く」通知。研修中は `hatake-gottani.games.enabled` と連動して通知のみ。

### ★ `dev-utils` 開発ユーティリティ集（ベテラン向け実用枠）
選択テキストや入力に対して: JSON 整形/圧縮、Base64・URL エンコード/デコード、UNIX 時刻 ⇔ 日時、UUID 生成、ハッシュ（SHA-256 等）、文字数/バイト数カウント、全角⇔半角変換、cron 式の日本語解説。
- コマンドパレット・右クリックメニューからエディタの選択範囲に直接適用できるようにする（Webview 不要なものは `kind: 'command'`）

### 基盤: お気に入り・最近使った・日替わり Tips
- ツリー最上部に「★お気に入り」「最近使った」グループ
- 日替わり Tips（VS Code の小技・Linux コマンド・言語の豆知識）をホームに表示。起動時通知は既定オフ

| ★`daily-challenge` | 日付をシードに全員同じお題（タイピング文・パズル配置）を生成。通信なしでも「今日のお題何秒だった？」と会話のきっかけになる |
