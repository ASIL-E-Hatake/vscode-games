## 進め方

- 機能はこまめに作るが、**リリースはある程度機能がまとまってから**行う（利用者が何度も入れ直さなくて済むように）。
- バージョンごとに統合ブランチ `verX_Y_Z`（例: `ver0_2_0`）を `main` から作り、機能ごとのブランチの PR はそこへ出す。
- 目安: **機能 4〜6 個、または 1〜2 か月**たまったら `verX_Y_Z` → `main` の PR を出してリリースする。
- 社内試用のフィードバック（Issue の `feedback` ラベル）は、内容に応じて次のバージョンに入れるかバックログに回す。
- このファイルの更新: バージョンの中身を決めた・変えたとき、機能の状態が変わったとき（PR を出した・マージした）。

| ✅ | `game-typing` | タイピングの苦手問題の復習 | 高 | M | 可 |
| ✅ | `game-kit` ほか | ゴースト対戦（自分の過去のベストと競争） | 高 | M | 共通部品を先に、各ゲームは並行可 |
| ✅ | `glossary` | 技術用語図鑑 | 高 | M | 可 |

進めた順番: ① game-kit の結果画面とゴーストの共通部品 → ② 苦手問題の復習・技術用語図鑑・ゴースト（スライドパズル）を並行 → ③ タイピングのレベル設定・鬼モードとゴースト（タイピング）。

### タイピングの苦手問題の復習

- **記録するもの**: お題ごとのミス回数と最後に間違えた日、文字ごとのミス（今の「苦手な文字」）。直近 50 件まで。
- **遊び方**: モード選択に「苦手復習」を追加。ミスが多かったお題から優先して出し、ミスなしで 2 回続けて打てたお題は「克服」として復習リストから外す。苦手が無いときは「まだ苦手はありません」と表示。
- **結果画面**: 「今回克服したお題」「まだ苦手なお題」を表示。復習モードは自己ベストを記録しない（練習用）。
- **広げ方**: ショートカット早押しクイズの「間違えた問題」、v0.4.0 の出力当てクイズにも同じ考え方を使う。2 つ目を作る時点で、共通の「復習リスト」部品にするか判断する。

### ゴースト対戦（自分の過去のベストと競争）

- 自己ベストを出したプレイの「経過」を保存し、次のプレイ中に自分と並べて表示する（ベストが無いときは表示しない）。
- **タイピング**: ベスト時の 1 秒ごとの入力文字数 → プレイ中に「ゴーストより 12 文字リード」のような 2 本の進捗バー。
- **スライドパズル**: ベスト時の経過時間ごとの「正しい位置のタイル数」→ 進捗バーで比較。
- **反射神経テスト**: ラウンドごとの反応時間を、結果画面でベストと並べて比較。
- 設定またはルール説明画面でオン / オフ（集中したい人向け）。保存はモードごとにベスト 1 件分だけ。
- 経過の記録（時刻と値の配列、間引き）と表示（進捗バー）は game-kit の共通部品にする。

### 技術用語図鑑

- **データ**: `content/glossary/`（用語・読み・分類（Java / Python / JavaScript / Ruby / Git / Linux / VS Code / 一般）・短い説明・関連する辞書やチートシートへの移動先）。最初は 80〜100 語。
- **ゲームで出会った用語**: タイピングのお題・エラーメッセージ辞書・クイズに用語のタグを付け、遊んだり開いたりすると「発見」として記録する。図鑑には発見済みの用語と未発見の用語（「？？？」）を並べ、収集率を表示する（集める楽しみ）。
- 用語を開くと、意味・どのゲームや辞書で出会ったか・関連する辞書への移動ボタン。検索・分類の絞り込み。
- 研修方針に合わせ、説明は短く、詳しくは公式ドキュメントへ（答えを与えすぎない）。
- v0.6.0 の実績（「図鑑 50%」など）・v0.4.0 のシークレット問題と連動させやすい。

### レベル設定（難易度）とタイピングの鬼モード

- 各ゲームに 2〜3 段階の難易度を「モード」として追加する（モード別の自己ベストの仕組みを使い、今の遊び方の記録は `legacy` で引き継ぐ）。
- **タイピング**
  - かんたん: 短いお題・記号少なめ / ふつう: 今のまま
  - **鬼（修正タイピング）**: わざと誤り（typo）を入れたコードを表示し、**正しいコードを打つ**。誤りの種類は「括弧・セミコロンの抜け」「キーワードの綴り（`retrun`）」「引用符の不一致」「`=` と `==` の取り違え」「インデントのずれ」など。正しいコードは今のお題そのもので、誤りは機械的に作る（お題を増やすたびに手で作らなくてよい）。結果画面に「見つけた誤り / 見落とした誤り」を表示。コードの誤りに気づく目を鍛える。
- **スライドパズル**: 5×5 を追加。
- **反射神経テスト**: 待ち時間のばらつきを大きく・No-Go の割合を高くした上級。
- **ショートカット早押しクイズ**: 誤答を同じ分類からだけ選ぶ・制限時間を短くした上級。
- 毎回ランダムに追加ルールが付く「ランダム縛り」（v0.6.0）とは別。レベルは決まったルールの組み合わせ。

## v0.4.0 — 頭を使うゲーム（リリース済み）

タイピング（指）や反射神経（反応）とは違う、**コードを読んで考える**ゲームを足す。問題の作り方・共有の仕組みもここで整える。

| 状態 | ID | 内容 | 優先度 | 工数 | 並行作業 |
|---|---|---|---|---|---|
| ✅ | `quiz-kit` | コード問題の共通部品（出題・回答・解説・問題データの形式・CI での実行検査） | — | M | **先に入れる** |
| ✅ | `game-output-quiz` | 出力当てクイズ | 高 | M | quiz-kit の後、並行可 |
| ✅ | `game-bug-hunt` | バグ探し | 高 | M | quiz-kit の後、並行可 |
| ✅ | `content-pack` | 問題パックのインポート（自作の問題集を JSON / YAML で追加） | 中 | M | 可 |
| ✅ | `game-kit` | コンボ・特殊演出（連続正解で演出・スコア倍率） | 中 | S | 可 |
| ✅ | — | シークレット問題（条件を満たすと隠し問題） | 中 | S | 図鑑・quiz-kit の後 |

### 出力当てクイズ

- 短いコード（5〜15 行）を読み、出力を 4 択で答える。1 問 20 秒 × 10 問。言語と難易度を選ぶ。
- 誤答の選択肢は「よくある勘違い」から作る（境界の 1 ずれ、整数の割り算、参照の共有、文字列と数値の連結、変数のスコープ など）。
- 間違えた問題だけ解説（どこでどう値が変わるか）を表示。苦手の復習（v0.3.0）と同じ考え方で再出題できるようにする。
- **問題のコードは CI で実際に実行し、正解の出力が本当に出るか検査する**（エラーメッセージ辞書と同じ仕組み）。

### バグ探し

- 数行〜十数行のコードと「本当はこう動いてほしい」という説明を見て、バグのある行を選ぶ（クリック・行番号キー）。1 問 30 秒 × 8 問。
- 解説は「その行で何が起きているか」まで。研修方針に合わせ、直したコードそのものは見せない。
- 問題のコードも CI で実行し、説明どおりに動かない（＝本当にバグがある）ことを確認する。
- 出力当てクイズと問題データの形式（コード・言語・難易度・解説・用語タグ）を共通にし、quiz-kit を共有する。

### 問題パックのインポート

- 自分やチームで作った問題（出力当て・バグ探し・タイピングのお題）を JSON / YAML で追加できるようにする。リンク集の「インポート・共有ファイル・ワークスペース」の仕組みを流用する（バックログの `content-pack`）。
- スキーマで検証し、不正な問題は読み飛ばして件数を表示。パックごとにオン / オフ。
- パックの問題で遊んだ記録は、同梱の問題の自己ベストとは分けて記録する（公平性のため）。
- 研修担当が「今週の課題に合わせた問題集」を配る使い方を想定。

### コンボ・特殊演出

- クイズ・タイピングで連続正解するとコンボ数を表示し、スコアに倍率（例: 5 連続で ×1.2、10 連続で ×1.5）。ミスでリセット。
- 演出は控えめにする（点滅なし、効果音は設定がオンのときだけ）。倍率の有無で記録が変わるので、導入時に自己ベストの扱いを決める（別モードにする等）。

### シークレット問題

- 条件（例: ノーミスで 10 問正解、図鑑の収集率 50%、特定の時間帯に遊ぶ）を満たすと隠し問題が出る。見つけたら図鑑・実績に記録する。
- 条件と問題はコンテンツ側で定義する（コードを書かずに増やせる）。

### 日替わりチャレンジ

- 日付をシード（乱数の種）にして、**全員同じお題**（タイピングのお題・パズルの配置・クイズの問題）を出す。通信なしでも「今日のお題、何秒だった？」と会話のきっかけになる。
- 1 日 1 回の記録（日付ごと）と連続参加日数。ホームに「今日のチャレンジ」カード。
- 結果をクリップボードにコピー（チャットに貼れる短い文字列。拡張機能は通信しない）。
- 「今日の縛り」（ランダム縛りプレイ）とも組み合わせられる。

### ゲーム内実績

- 例: 「Java のお題を 100 問打った」「自己ベストを更新した」「Go/No-Go をノーミス」「図鑑を 50% 集めた」「日替わりチャレンジに 7 日連続で参加」。
- ホームに獲得数、実績の一覧画面（獲得済み / 未獲得、条件のヒント）。新人には研修のスタンプカードとしても使える。
- 各ゲームは「出来事」（○○を打った・ベスト更新 など）を記録するだけにし、実績の判定は共通部品で行う（ゲームごとに判定を書かない）。

### ランダム縛りプレイ

- 遊ぶたびに追加ルールがランダムに付く: 記号の多いお題だけ / 大文字小文字を厳密に / 制限時間 30 秒 / Backspace 禁止 など。
- 縛りで遊んだ記録は通常の自己ベストとは分け、縛りの種類ごとに最高記録を残す。

## 並行して作るときの注意

複数の機能を同時に作る（複数人・複数の Claude Code セッション）ときは、次のファイルが衝突しやすい。

| ファイル | 衝突の内容 | 対処 |
|---|---|---|
| `src/features/index.ts` | 登録の 1 行追加 | アルファベット順の 1 行なので、統合ブランチを取り込んで並べ直すだけ |
| `CHANGELOG.md` | `[Unreleased]` への追記 | 各自 1 行ずつ追記。衝突したら両方残す |
| `package.json` | コマンド・設定の追加 | 同上 |
| `.github/ISSUE_TEMPLATE/1-feedback.yml` | 「機能」の選択肢の追加 | 同上（テストで機能名との一致を検査している） |
| `docs/roadmap.md` | 状態の更新 | 統合ブランチへのマージ後にまとめて更新してもよい |
| 共通基盤（`src/core/`・`src/webview-shared/`） | 仕様の変更 | **並行作業に向かない**。先に共通基盤だけの PR を統合ブランチに入れてから、各機能を始める |
| 同じ機能のフォルダ（例: `src/features/game-typing/`） | 同じ画面・ロジックの変更 | 同じ機能への変更は並行せず順番に行う |
