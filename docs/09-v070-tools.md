# v0.7.0 の設計 — QR コード・バーコード・AI への依頼文テンプレート・リンク集のタブ化

> ステータス: 決定（2026-10-20）。ロードマップは [roadmap.md](roadmap.md) の v0.7.0。
> 共通方針は v0.5.0 のツールと同じ（[07-tool-generators.md](07-tool-generators.md) 1 章: 生成物はコピー / 保存だけ・外部通信なし・データで増やせる）。

## 1. 機能の一覧

| ID | 名前 | 入力 → 生成 | 担当の目安 |
|---|---|---|---|
| `qr-code` | QR コード | 種類（URL・テキスト・連絡先 vCard・Wi-Fi・メール・電話・SMS）を選んでフォームに入力 → QR コード。画像（PNG / SVG）でコピー・保存、文字（例: `■` / `██`）で表したテキストもコピーできる。真ん中に画像を入れられる | M |
| `barcode` | バーコード | 種類（JAN / EAN-13・EAN-8・Code128・Code39）を選んで値を入力 → バーコード。画像（PNG / SVG）でコピー・保存 | S |
| `ai-prompt` | AI への依頼文 | やりたいこと（プログラムを作りたい・調べてほしい・データを分析してほしい…）を選び、事前に伝えるべきことを複数の入力欄に書く → AI にそのまま渡せる依頼文（コピー） | M（データが中心） |
| `links` | リンク集の改修 | カテゴリをタブにする（辞書・チートシートと同じ部品・操作） | S |

QR コードとバーコードは「画像を作ってコピー・保存する」部分を共通にする（`src/webview-shared/imageExport.ts`。下の 2.3）。

## 2. QR コード（`qr-code`）

### 2.1 種類と入力

| 種類 | 入力欄 | QR に入れる文字列 |
|---|---|---|
| URL | URL（http / https） | そのまま |
| テキスト | テキスト（複数行） | そのまま（UTF-8） |
| 連絡先（vCard） | 氏名（姓・名）・ふりがな・会社・部署・役職・電話・メール・URL・住所 | `BEGIN:VCARD` `VERSION:3.0` … `END:VCARD`（値の `\` `;` `,` 改行はエスケープ） |
| Wi-Fi | ネットワーク名（SSID）・パスワード・暗号化（WPA / WEP / なし）・ステルス | `WIFI:T:WPA;S:<SSID>;P:<パスワード>;H:true;;`（`\` `;` `,` `:` `"` はエスケープ） |
| メール | 宛先・件名・本文 | `mailto:` + クエリ（パーセントエンコード） |
| 電話 | 電話番号 | `tel:` |
| SMS | 電話番号・本文 | `SMSTO:<番号>:<本文>` |

- 入力のたびに作り直す。必須項目が空なら「〇〇を入れてください」。文字数が多すぎて入らないときは、その旨と今の文字数・上限を出す。
- 入力を組み立てる処理（vCard・Wi-Fi のエスケープなど）は DOM 非依存の純粋関数にし、L1 で検査する。
- Wi-Fi のパスワードなど秘密の値は**保存しない**（画面を閉じたら消える）。ほかの入力は保存してよい。

### 2.2 見た目の設定

- **誤り訂正レベル**: L / M / Q / H（既定 M。真ん中に画像を入れるときは自動で H にし、その旨を表示）。
- **表し方**: 画像（黒い四角）/ **文字**。文字のときは 1 マスを表す文字を選べる（`██`・`■`・`#`・任意の 1 文字）。空白側の文字も選べる（全角空白・半角空白 2 つ）。文字のときはテキストとしてコピーする（チャット・テキストファイルに貼れる）。
- **色**: 前景・背景（既定は黒・白。読み取れなくなるのを防ぐため、明暗の差が小さい組み合わせは警告）。テーマの色は使わない（印刷・読み取り用のため固定色。ルール 3 の例外として明記）。
- **余白（クワイエットゾーン）**: 既定 4 マス。
- **真ん中の画像**: 画像ファイル（PNG / JPEG / SVG）を選ぶ（ホスト側のファイル選択ダイアログ。コマンドは引数で URI を受け取れるようにする: ルール 12）。大きさは QR の 15〜25% の範囲（既定 20%）。画像の周りに背景色の余白を付ける。画像はこの画面の中だけで使い、どこにも送らない。

### 2.3 コピー・保存（QR・バーコード共通の `imageExport`）

- **画像としてコピー**: Webview の `navigator.clipboard.write([new ClipboardItem({ 'image/png': blob })])` が VS Code の Webview で使えるかを**最初に確かめる**（使えない場合は「保存」だけにして、画面に理由を出す）。
- **保存**: PNG（大きさを選ぶ: 256 / 512 / 1024 px）と SVG。Webview で作ったデータをホストに渡し、保存ダイアログで保存する（`vscode.window.showSaveDialog` → `workspace.fs.writeFile`）。コマンドは引数で保存先 URI を受け取れる。
- **テキストとしてコピー**: 文字で表した QR、SVG のソース。

### 2.4 ライブラリ

- QR の符号化（データの分割・誤り訂正）は**小さなライブラリを 1 つ**入れる（決定事項）。条件: MIT 等の緩いライセンス・依存なし・外部通信なし・Webview のバンドルに入れて数十 KB 以内。候補は `qrcode-generator`・`uqr` など。担当が比べて決め、理由とバンドルサイズを PR に書く（ルール 9）。
- 描画（canvas / SVG / 文字）は自前。
- 生成した QR が正しく読めることを L1 で確かめる（例: 規格の例・ライブラリのテスト用データと突き合わせる。読み取りライブラリを devDependencies に入れて往復で確かめるのも可）。

## 3. バーコード（`barcode`）

| 種類 | 入力 | 備考 |
|---|---|---|
| JAN / EAN-13 | 12 桁（13 桁目のチェックディジットは自動で計算。13 桁を入れたら正しいかを確かめる） | 日本の商品コード（先頭 45 / 49） |
| EAN-8 | 7 桁（同上） | 短縮版 |
| Code128 | 英数字・記号（ASCII） | 一般的な英数字のバーコード。コードセットの切り替えは自動 |
| Code39 | 英大文字・数字・`- . $ / + %` と空白 | 古い業務システム向け |

- 符号化は自前（純粋関数。規格の例と突き合わせて L1 で検査）。
- 下に数字・文字を表示する / しないを選べる。バーの高さ・幅の倍率。色は QR と同じ（前景・背景、明暗差の警告）。
- 不正な文字・桁数はどこが不正かを表示する。
- コピー・保存は QR と共通（2.3）。

## 4. AI への依頼文テンプレート（`ai-prompt`）

### 4.1 ねらい

AI に依頼するとき、人間が最初に出すべき情報（目的・前提・制約・出力の形）が足りないと、的外れな答えや何度もの聞き返しになる。
**やりたいことを選ぶと「事前に書いておくこと」の入力欄が出て、埋めるとそのまま AI に渡せる依頼文ができる**。入力欄ごとに「なぜ必要か」を一言添え、依頼の仕方も覚えられるようにする。

- 対象は全員（決定事項。新人研修ではプログラム研修の後に AI 研修がある。プログラム研修の課題で使うかどうかは本人の責任）。
- 画面の上に注意を常に出す: 「会社の AI 利用ルールに従ってください。社外秘・顧客情報・個人情報・パスワードは入力しないでください」。
- 拡張機能は AI に送らない（**コピーするだけ**。外部通信なし）。

### 4.2 データの形（`content/ai-prompts/*.yaml`）

```yaml
version: 1
templates:
  - id: build-program
    category: develop          # develop / investigate / analyze / write / learn
    title: プログラムを作ってほしい
    summary: 新しいプログラム・スクリプト・機能を作ってもらう
    fields:
      - id: goal
        label: 作りたいもの
        type: textarea         # text / textarea / select / checkbox
        required: true
        placeholder: 例: CSV の売上データを月ごとに集計して、グラフ用の CSV を出すスクリプト
        why: 何を作るかが具体的なほど、余計な機能や見当違いが減る
      - id: language
        label: 言語・フレームワーク・バージョン
        type: text
        placeholder: 例: Python 3.12、pandas を使ってよい
        why: 指定が無いと、環境で動かない書き方を選ばれることがある
      # …
    output: |                  # {{id}} を入力値に置き換える。{{#id}}…{{/id}} は入力があるときだけ出す
      次のプログラムを作ってください。

      ## 作りたいもの
      {{goal}}
      {{#language}}

      ## 言語・環境
      {{language}}
      {{/language}}
      …
      ## お願い
      - 不明な点があれば、作り始める前に質問してください。
      - 前提を置いた場合は、その前提を最初に書いてください。
```

- 出力は Markdown（見出しで区切る）。最後に「不明点は先に質問して」「前提を明記して」など、AI の答えの質を上げる共通の一文を付ける（テンプレートごとに変えてよい）。
- 必須項目が空なら依頼文を出さず「〇〇を入れてください」。任意の項目は空なら見出しごと出さない。
- 入力は保存する（同じテンプレートを開き直すと戻る）。「入力を消す」ボタン。
- テンプレートの追加はデータだけでできる（L2 でスキーマ・ID の重複・`output` の `{{id}}` が `fields` にあるか・必須項目が `output` で使われているか を検査）。
- 2 段階目: チーム独自のテンプレートを問題パックと同じ仕組みで共有（今回は同梱のみ）。

### 4.3 収録するテンプレート（よく頼まれる依頼のパターン）

各テンプレートの入力欄は「これが無いと AI が推測で埋めてしまい、精度が落ちるもの」に絞る（多すぎると誰も使わない。必須は 1〜3 個）。

| 分類 | テンプレート | 主な入力欄（★ = 必須） |
|---|---|---|
| 作る | プログラムを作ってほしい | ★作りたいもの / ★入力と出力（例付き）/ 言語・環境・バージョン / 使ってよい・いけないライブラリ / 動かす場所（PC・サーバー・ブラウザ）/ 規模の感覚（使い捨て・長く使う）/ 出力の形（全文・差分・手順付き） |
| 作る | 今のコードに機能を足してほしい | ★今のコード（関係する部分）/ ★足したいこと / 変えてはいけないところ / 言語・環境 / コードの書き方の決まり |
| 作る | エラー・不具合を直したい | ★起きていること（エラーメッセージ全文）/ ★期待していた動き / 関係するコード / 再現手順 / 環境（OS・言語・バージョン）/ もう試したこと |
| 作る | コードをレビューしてほしい | ★コード / 何のためのコードか / 特に見てほしい観点（バグ・性能・読みやすさ・セキュリティ）/ チームの決まり / 指摘の形（重要度順・修正案付き） |
| 作る | テストを書いてほしい | ★テストしたいコード / テストの道具（JUnit・pytest・Vitest 等）/ 確かめたい場合（正常・境界・異常）/ 既存のテストの書き方の例 |
| 作る | SQL を書いてほしい | ★やりたいこと（取りたいデータ）/ ★テーブルの定義（列・型・関係）/ データベースの種類とバージョン / データ量の感覚 / 結果の例 |
| 作る | 正規表現を作ってほしい | ★当てはまってほしい例 / ★当てはまってほしくない例 / 使う場所（言語・grep・エディタ）/ 置換するならその後の形 |
| 作る | リファクタリングしてほしい | ★コード / ★直したい理由（読みにくい・遅い・重複）/ 変えてはいけない振る舞い / テストの有無 |
| 調べる | 情報を集めて・調べてほしい | ★調べたいこと / ★何に使うか（判断・資料・学習）/ 期間・地域・対象の範囲 / 信頼できる情報源の条件（公式・一次情報）/ まとめ方（表・箇条書き・比較）/ 出典を付けるか |
| 調べる | 技術・製品を比較してほしい | ★比べたいもの（候補）/ ★選ぶ目的・使い道 / 重視する観点（費用・性能・学習のしやすさ・サポート）/ 制約（社内の環境・予算）/ 出力の形（比較表＋おすすめ） |
| 調べる | 設計・方針を相談したい | ★作りたいもの・解きたい課題 / 今の構成・制約 / 考えている案 / 気にしていること（規模・保守・費用）/ 決めたいこと |
| 分析する | データを分析してほしい | ★分析の目的（何を知りたい・何を決めたい）/ ★データの説明（列の意味・件数・期間）/ データの例（数行。個人情報は伏せる）/ 使う道具（Excel・Python・SQL）/ 欲しい結果（集計表・グラフ・考察）/ 注意する偏り・欠損 |
| 分析する | ログ・エラーの傾向を見てほしい | ★ログの一部 / ★知りたいこと（原因・頻度・時間帯）/ ログの形式の説明 / 期間・件数 |
| 書く | 文章を書いてほしい（メール・報告・案内） | ★目的（依頼・お詫び・報告・案内）/ ★相手と関係（社内・社外・上司）/ ★伝えたい内容（箇条書きでよい）/ 文体・長さ / 期限・日時など必ず入れる事実 |
| 書く | 文章を直してほしい（校正・要約・言い換え） | ★元の文章 / ★直してほしいこと（誤字・読みやすさ・短く・丁寧に）/ 読む人 / 変えてはいけない言葉 |
| 書く | 資料・ドキュメントを作ってほしい | ★テーマ / ★読む人と目的 / 盛り込む内容 / 分量・構成（スライド何枚・見出し）/ 形式（Markdown・表） |
| 書く | 議事録をまとめてほしい | ★メモ・書き起こし / 会議の目的・参加者 / まとめ方（決定事項・ToDo・担当・期限） |
| 書く | 翻訳してほしい | ★元の文章 / ★訳す先の言語 / 用途（メール・技術文書・UI）/ 用語の決まり / 文体 |
| 学ぶ | 概念・仕組みを説明してほしい | ★知りたいこと / ★自分の今のレベル（初めて・少し知っている）/ 何のために知りたいか / 説明の形（たとえ・図・例のコード）/ 次に何を学べばよいかも知りたいか |
| 学ぶ | エラーメッセージの意味を知りたい（答えではなくヒント） | ★エラーメッセージ / ★やろうとしていたこと / 自分で調べたこと / 「直し方の答えではなく、調べ方・考え方のヒントがほしい」の選択 |

- 「学ぶ」の分類は、答えをそのまま求めない頼み方（ヒント・考え方を聞く）を選べるようにする（研修中の新人にも役立つ）。
- テンプレートは 20 件。文章は担当が書き、L2 で形を検査する。研修の課題の答えになる例（具体的な課題文）は書かない。

### 4.4 画面

- 左にテンプレートの一覧（分類のタブ・検索）、右に入力欄と生成された依頼文（コピーボタン）。辞書・コマンド組み立てと同じ並び。
- 入力欄の下に「なぜ必要か」を小さく表示。必須には印。
- 生成された依頼文の文字数を表示（長すぎるときの目安）。

## 5. リンク集のタブ化（`links`）

- カテゴリをタブにする（「すべて」＋カテゴリ。辞書・チートシートと同じ共通部品）。検索・出どころの絞り込み・個人リンクの操作は今のまま。選んだタブは保存する。
- 詳しい動きは担当が既存の辞書に合わせて決め、PR に書く。

## 6. テスト

| 層 | 内容 |
|---|---|
| L1 | QR の入力の組み立て（vCard・Wi-Fi・mailto のエスケープ）・文字表現・色の明暗差、バーコードの符号化とチェックディジット（規格の例と突き合わせ）、AI テンプレートの組み立て（`{{id}}`・`{{#id}}`・必須の判定）、リンク集のタブの作り方 |
| L2 | AI テンプレートのスキーマ・ID の重複・`output` と `fields` の対応 |
| L3 | 各画面の表示・キーボード操作・コピー（メッセージ）・保存（ホストへのメッセージ）・3 テーマのスクリーンショット・axe |
| L4 | 各パネルが開く・保存コマンドに URI を渡して PNG / SVG が書ける・画像選択コマンドに URI を渡して真ん中の画像が読める |
